# OpenRISC 1000 processor module for Ghidra

A SLEIGH processor module for OpenRISC 1000 (or1k), the 32-bit ORBIS32 instruction set with
the ORFPX32 and ORFPX64A32 floating-point extensions. It is a community module that
Ghidra-Rare imported, tested against GNU binutils, and fixed:

- [smaeul/ghidra-or1k](https://github.com/smaeul/ghidra-or1k) by Samuel Holland, with the
  little-endian variant from
  [Spritetm/ghidra-or1k-le-hack](https://github.com/Spritetm/ghidra-or1k-le-hack) by Jeroen
  Domburg.
- Apache-2.0.
- See [CREDITS.md](CREDITS.md) for the upstream commits and every Ghidra-Rare change.
- It targets Ghidra 12.1.4, and also builds on 12.1.3 and 12.2.

## Languages

| Language ID | Description | ELF auto-select |
|---|---|---|
| `OpenRISC:BE:32:default` | OpenRISC 1000, big endian, delay slots (the standard or1k ABI; Linux, newlib, gcc) | e_machine 92 (EM_OPENRISC) or 0x8472, ELF32 MSB |
| `OpenRISC:LE:32:default` | Little endian, no delay slot (CPUCFGR[ND]), as used by hx330x camera SoCs | e_machine 92, ELF32 LSB |

## Files

- `data/languages/OpenRISC.slaspec` holds the registers, tokens and variant switches.
  `OpenRISC-le.slaspec` sets `ENDIAN=little` and `NO_DELAY_SLOT`.
- `OpenRISC_ORBIS32.sinc` is the integer instruction set.
- `OpenRISC_ORFPX.sinc` holds single and double precision, the latter on register pairs. It
  is generated by `tools/gen_orfpx.py`.
- `OpenRISC_SPRs.sinc` maps the special-purpose registers into register space. It is
  generated by `tools/sprs.py`.
- `OpenRISC.cspec` has the calling convention. Arguments go in r3–r8, then on the stack at
  r1+0, and 64-bit values use register pairs with the most significant word first. Results
  are in r11 or r11:r12. The link register is r9.
- `OpenRISC.pspec`, `OpenRISC.ldefs`, `OpenRISC.opinion` and `OpenRISC.dwarf` are the other
  spec files. `OpenRISC.dwarf` is the gcc DWARF register map.
- `data/patterns` holds function-start patterns for big endian.
- `src/main/java/.../OpenRISC_ElfRelocationHandler.java` handles the `R_OR1K_*`
  relocations.
- `src/main/java/.../OpenRISC_ElfExtension.java` sets r16 to the GOT over `.plt`, so PIC PLT
  stubs become thunks named after their `JMP_SLOT` symbols.

## Semantics

There is real p-code for the following:

- The integer ALU, with the carry (`CY`) and overflow (`OV`) flags as separate registers.
- Compares into the flag `F`, `l.cmov`, `l.ff1`/`l.fl1` and `l.ext*`.
- Multiply and divide, including `l.muld`/`l.muldu` and the MAC unit (`l.mac*`, `l.msb*`,
  `l.macrc` on `MACHI`/`MACLO`).
- Loads and stores, and `l.lwa`/`l.swa` (the store always succeeds and sets `F`).
- `l.mfspr`/`l.mtspr`, which address the SPR register space by number.
- Branches, calls and returns with delay slots on BE and without them on LE, and `l.adrp`.
- Single and double precision float: arithmetic, conversions and every ordered and unordered
  compare.

These are modelled specially:

- **System calls.** `l.sys K` falls through as `r11 = syscall(K, r11, r3..r8)`, the Linux
  convention. `l.trap K` is a `trap(K)` pcodeop that falls through.
- **Exception return.** `l.rfe` is a return through `EPCR0`.
- **Reading the PC.** `l.jal 8` (`l.jal 4` without delay slots) is how PIC code reads the PC.
  It sets r9 and falls through instead of being a call.
- **Pcodeops.** `l.cust1`–`l.cust8`, `lf.cust1`, `lf.rem` and the sync instructions are
  pcodeops.

## Test results

Run `test/run-tests.sh` for the synthetic tests, and `test/fetch-real-samples.sh` then
`test/real-binaries.sh` for real binaries (see "Testing" below).

### Decoding vs GNU objdump 2.45

The BE language is compared with `objdump -m or1k -EB`, and the LE language with
`objdump -m or1knd -EL`. The `table` corpus holds every entry of the binutils opcode table
(`opcodes/or1k-opc.c`, 142 entries) plus the four architecture-manual encodings binutils
lacks. Each entry appears with its operand bits all 0, all 1, and with 40 random fills. The
`fuzz` corpus is 50,000 uniformly random words. A word that both tools reject counts as
agreement.

| Corpus | Words | Agreement | Exact + semantic among decoded words | Unexplained differences |
|---|---|---|---|---|
| table, BE | 6,090 | 95.16 % | 5,788 / 6,083 | 0 |
| fuzz, BE | 50,000 | 98.45 % | 19,003 / 19,776 | 0 |
| table, LE | 6,090 | 95.16 % | 5,788 / 6,083 | 0 |
| fuzz, LE | 50,000 | 98.45 % | 19,003 / 19,776 | 0 |

"Semantic" means the same instruction with numbers in another base. Ghidra prints hex where
objdump prints decimal, and objdump prints bare-hex branch targets in linked files.

Every difference falls into one of three classes, and `compare.py` reports each one:

1. **Architecture-manual instructions binutils 2.45 does not decode:** `l.lf` (opcode 0x1a,
   since arch 1.3), `lf.stod.d` and `lf.dtos.d`. Ghidra decodes them as the manual
   specifies (771 of the fuzz words; 119 table words).
2. **`l.muldu`.** The OpenRISC 1000 manual (1.4, p. 90) and QEMU
   (`target/or1k/insns.decode`) give it secondary opcode 0xc. binutils
   (`cpu/or1korbis.cpu`, `OPC_ALU_REGREG_MULDU #xD`) uses 0xd, and that is still so on
   binutils master. This module follows the manual. None of the real samples contains
   either encoding.
3. **ORFPX64A32 register pairs past r31.** When rN is r31 (or r30 with the +2 pair bit),
   objdump prints a pair such as `r31,r33`. Those registers do not exist, so Ghidra rejects
   the word (92 table words; 2 fuzz words).

**Every-entry test** (`test/entry_check.py`): all 145 table entries decode in Ghidra with
their own mnemonic, both with operand bits 0 and with operand bits 1, on BE and on LE. The
only exceptions are the binutils `l.muldu` encoding and the all-ones register-pair forms
(classes 2 and 3 above).

### Emulator

`test/emu_tests.py` and `test/EmuCheck.java` run 33 instruction sequences per language in
Ghidra's p-code emulator and check registers and memory against hand-computed values. They
cover:

- Add, add-with-carry and subtract, checking CY and OV.
- Logic, register and immediate shifts and rotates (including shift amounts of 32 or more),
  and signed and unsigned multiply and divide.
- `l.ext*`, `l.ff1`/`l.fl1`, `l.cmov`, and signed versus unsigned compares.
- Word, half and byte loads and stores, including the split store offset.
- MAC and `l.macrc`, `l.muldu`, `l.mtspr`/`l.mfspr`.
- Single precision, double precision on register pairs (both pair offsets) and `lf.dtos.d`.
- Calls and returns, `l.jalr`, taken and not-taken branches with and without delay slots, a
  loop, the PC read and `l.adrp`.

Results: 33/33 on BE and 33/33 on LE. With `--break N` the generator makes one expectation
wrong, and the check then reports exactly that test as failed.

### Compiled test program and relocations

`test/elf/` holds a C program built with Bootlin gcc 14.3.0. It uses every optional
extension: `-mhard-float -mdouble-float -mcmov -msext -mror -mrori -msfimm -mshftimm`.

- **`or1ktest.elf`:**
  - 20 functions, 500 instructions, 100 % identical to objdump.
  - 0 bad instructions, and all 20 functions decompile.
  - Float and double code (`lf.*.s`, `lf.*.d` on register pairs, `lf.ftoi.d`) decompiles to
    float expressions.
  - DWARF prototypes import.
- **Relocation handler (`test/reloc-check.sh`).** Ghidra imports `relocs.o` and
  `or1ktest.o` and applies their relocations at the addresses it chooses. The same objects
  linked by GNU ld at those addresses must be byte-identical:
  - `relocs.o`: 19 relocations, 144 bytes, 0 differ.
  - `or1ktest.o`: 266 relocations, 740 bytes, 0 differ.
  - Types checked against ld: `32`, `32_PCREL`, `HI_16_IN_INSN`, `LO_16_IN_INSN`, `AHI16`,
    `SLO16`, `INSN_REL_26`, `PLT26`, `PCREL_PG21`, `LO13`, `SLO13`.

### Real binaries

`test/fetch-real-samples.sh` downloads the samples (pinned URL and SHA-256; nothing is
committed):

- **Bootlin `openrisc--glibc--stable-2025.08-1`:** glibc `libc.so.6`, `libm.so.6`,
  `ld-linux-or1k.so.1` and the static `ldconfig` (LGPL/GPL).
- **QEMU Advent Calendar 2018 day 20:** an OpenRISC Linux kernel `vmlinux` (GPL-2.0).

`test/real-binaries.sh` imports each one headless with no `-processor` flag (the opinion
picks `OpenRISC:BE:32:default` for all five), runs auto-analysis and decompiles every
function. It then compares every instruction Ghidra found with objdump at the same address.

| Sample | Functions | Bad instr. bookmarks | Decompiled | Disassembly vs objdump | Relocations |
|---|---|---|---|---|---|
| `ldconfig` (static) | 1,342 | 49 (see below) | 1,342 / 1,342 | 178,030 / 178,030 (100 %) | – |
| `ld-linux-or1k.so.1` | 282 | 0 | 282 / 282 | 39,432 / 39,432 (100 %) | 19 applied |
| `libc.so.6` | 3,201 (60 PLT thunks) | 0 | 3,170 / 3,170 (+13 EXTERNAL stubs) | 361,823 / 361,823 (100 %) | 1,050 applied, 12 TLS reported |
| `libm.so.6` | 451 | 0 | 439 / 439 (+6 EXTERNAL stubs) | 119,350 / 119,350 (100 %) | 13 applied, 1 TLS reported |
| `vmlinux` (Linux kernel) | 9,027 | 1 (entry word, see below) | 9,027 / 9,027 | 614,854 / 614,854 (100 %) | – |

No decompile failed or timed out (60 s limit per function). In the decompiled code:

- PLT calls resolve to named thunks (`malloc`, `realloc`, `abort`...).
- GOT-relative globals resolve.
- System calls appear as `syscall(...)`.
- Unaffected-register inputs are almost all `unaff_r10`. That is the thread pointer in
  glibc and the current-thread pointer in the kernel, which is set outside the function.

Problems the real binaries found, all fixed (details in CREDITS.md):

| Problem | Before | After |
|---|---|---|
| `l.jal 8` (PC read in PIC code) modelled as a call | ldconfig: 2,314 functions, 34 KB of `.text` not disassembled, `extraout_r9` everywhere | 1,342 functions, 16 bytes not disassembled |
| Link address `inst_next + 4` (jump + 12 with a delay slot) | GOT pointer 4 bytes off in every PIC function | correct GOT references |
| No relocation handler | 1,063 libc relocations unapplied | 0 errors |
| PIC PLT stubs use r16 from the caller | 42 unnamed stubs with "could not recover jumptable" | named thunks |
| `l.sys` was a goto to 0xc00 | every function ended at its first system call | falls through |
| `l.cmov` in a delay slot (gcc `-mcmov`) | `smax` ran into the next function | correct |
| Prototype named `default` | "Unknown calling convention" on every DWARF-typed function | clean |

## Known gaps

- **glibc `vfprintf` jump tables.** In `ldconfig`, `__printf_buffer` and `__wprintf_buffer`
  reach their computed-goto label tables (the `step*_jumps` arrays) through a table pointer
  spilled to the stack. The table is reassigned on several paths, and the decompiler's
  jump-table recovery reads entries from the wrong place. It then disassembles 49 words of
  `.rodata` as code, which produces the 49 bad-instruction bookmarks. This is a decompiler
  limitation, not a decoding error. The same functions in `libc.so.6` do not trigger it.
- **Kernel entry and vectors.** The kernel's ELF entry point (`0xc0000000`) is a zero word,
  which decodes as `l.j .` with another `l.j .` in its delay slot. Ghidra reports that as one
  bad instruction. The exception vectors at `0xc0000100`… and the `__ex_table` fixup stubs are
  reached only by hardware or the exception table, so about 2,000 of their words are not
  disassembled unless the user marks them. The pspec's vector symbols (`0x100`, `0x200`, …)
  apply only to images loaded at 0.
- **SR flags.** `F`, `CY` and `OV` are separate registers. An `l.mfspr`/`l.mtspr` of `SR`
  does not read or write them.
- **Pcodeops.** Custom instructions (`l.cust*`, `lf.cust1`), `lf.rem` and the sync
  instructions are pcodeops. Exceptions such as overflow traps, range checks and alignment
  are not modelled.
- **`l.muldu`.** Binaries assembled by GNU as with `l.muldu` (secondary opcode 0xd) do not
  decode. That encoding conflicts with the architecture manual (see "Decoding" above).
- **TLS relocations.** These and GOT-model relocations in relocatable objects are reported,
  not applied. `R_OR1K_16`, `R_OR1K_8` and the `_PCREL` 16/8-bit types are implemented but
  not checked against ld: they overflow at Ghidra's addresses, and ld 2.43 asserts on
  `R_OR1K_16_PCREL`.
- **ORBIS64.** `l.ld`/`l.sd` and the 64-bit forms are not implemented. No 32-bit core
  uses them.
- **Little endian.** The LE, no-delay-slot language passes the decode and emulator suites,
  but no little-endian real binary was tested. hx330x firmware images are vendor binaries
  with no public license. Its ELF opinion entry is untested for the same reason.

## Confirmed reference-tool issues

- binutils 2.45 does not know the architecture-1.3 instructions `l.lf`, `lf.stod.d` and
  `lf.dtos.d`.
- binutils encodes `l.muldu` as secondary opcode 0xd, against the manual and QEMU (0xc).
- objdump prints nonexistent registers r32/r33 for ORFPX64A32 pairs that start at r31.
- GNU ld 2.43.1 (Bootlin) hits `BFD assertion fail elf32-or1k.c:1214` when it relocates
  `R_OR1K_16_PCREL`.

## Testing

```sh
export GHIDRA_INSTALL_DIR=/path/to/ghidra_12.1.4_PUBLIC   # with Ghidra/Processors/OpenRISC -> this module
export OBJDUMP=/path/to/binutils-2.45/objdump               # built with --enable-targets=all
export OR1K_OPC=/path/to/binutils-2.45/opcodes/or1k-opc.c
test/fetch-real-samples.sh samples --keep-toolchain         # optional: Bootlin toolchain + samples
export OR1K_TOOLCHAIN=$PWD/samples/openrisc--glibc--stable-2025.08-1/bin   # optional (relocation check)
test/run-tests.sh work                                      # decode, every-entry, emulator, test ELFs
test/real-binaries.sh samples work-real                     # real binaries (~15 min; the kernel dominates)
```

Other files in `test/`:

- `gen_corpus.py`, `compare.py` and `entry_check.py`: corpus generation and comparison.
- `DumpWords.java`: decodes each word on its own.
- `EmuCheck.java`: the emulator check.
- `RealCheck.java`: analysis, listing and decompile statistics.
- `DumpMem.java` and `rawcmp.py`: used by the relocation check.
- `build-jar.sh`: compiles `lib/OpenRISC.jar` for a development install. `gradle
  buildExtension` builds it for release zips.
- `elf/build.sh`: rebuilds the test ELFs from `or1ktest.c` and `relocs.s`.
